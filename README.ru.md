## Что делает

Вы ставите точку. Страница запрашивает почасовой прогноз для этих координат
в Open-Meteo — без ключа и с разрешёнными CORS, поэтому всё считается прямо
в браузере — и ведёт контур пожара по часам.

- **Временная шкала** внизу листает часы прогноза. Стрелки переключают кадры,
  пробел ставит на паузу.
- **Контур гари** растёт и изгибается вслед за разворотом ветра, итоговый
  охват показан пунктиром.
- **Дымовой шлейф** сносится по ветру текущего часа. Уже выпущенные частицы
  сохраняют свою скорость, поэтому при развороте ветра шлейф изгибается —
  как настоящий дым.
- **Настройки**: горизонт прогноза (3–24 ч), усыхание травостоя, размер
  начального очага.
- **Четыре подложки** — тёмная (по умолчанию), серая, спутник и OpenStreetMap,
  все с подписями.

Палитра выбрана не для красоты: на тёмной подложке светится контур пожара и
читается дым, а шлейф сиреневый потому, что серый на тёмной карте попросту
исчезает, тогда как холодный лиловый виден и не спорит с тёплыми цветами огня.

## Модель

Скорость головной части фронта по Cheney, Gould & Catchpole (1998):

```
U10 ≤ 5 км/ч:  R = (0.054 + 0.269·U10) · Φm · Φc
U10 > 5 км/ч:  R = (1.4 + 0.838·(U10−5)^0.844) · Φm · Φc
```

`Φm` — поправка на влагосодержание тонких горючих материалов, оценивается
по температуре и влажности; `Φc` — на усыхание травостоя (Cruz et al., 2015).
Распространение в стороны от оси ветра — по эллиптическому соотношению,
отношение длины к ширине `1.1·U10^0.464`.

Open-Meteo отдаёт направление, **откуда** дует ветер. Огонь идёт в обратную
сторону: `азимут = направление_ветра + 180°`.

### Как ведётся контур

Каждая вершина смещается вдоль своей внешней нормали со скоростью, зависящей
от угла между нормалью и ветром — принцип Гюйгенса. По мере расхождения
головной части в образующиеся разрывы вставляются новые точки.

Сглаживание не применяется, вершины не переразмечаются со сдвигом. И то,
и другое было опробовано и проваливается одинаково: срезает острый нос фронта
и занижает дальность втрое. Это зафиксировано в тестах — они сверяют положение
головы с аналитическим значением на каждом часе.

Опорные значения, проверяются при каждом прогоне:

| Ветер, км/ч | Скорость фронта, км/ч |
|---|---|
| 10 | 1.98 |
| 20 | 4.09 |
| 30 | 5.97 |

При усыхании ниже 50% модель перестаёт распространять огонь: зелёная трава
не горит.

## Ограничения

**Это индикативная оценка, а не оперативный прогноз.** Не используйте её для
решений об эвакуации и тушении. Модель не учитывает рельеф (вверх по склону
огонь идёт кратно быстрее), барьеры — реки, дороги, минполосы и вспашку,
порывистость ветра внутри часа, запас и неоднородность топлива, работу
пожарных расчётов.

Модель Cheney разработана на австралийских пастбищах. За их пределами это
аналог, а не откалиброванная местная модель. Она предполагает сплошной
травяной покров, поэтому результат над лесом, пашней, болотом или голой
землёй смысла не имеет.

Дальше нескольких часов ветер сам по себе прогнозный, и эта ошибка
накладывается на ошибку модели пожара.

Анимация дыма показывает приземный снос огня, **а не** дисперсию дымового
шлейфа. Настоящий дым поднимается в конвективной колонке и сносится ветром
на высоте. Для оценки качества воздуха нужна модель переноса примеси вроде
HYSPLIT.

## Разработка

```bash
npm test           # извлекает модель из index.html и гоняет 20 проверок
npm run serve      # http://localhost:8000
```

Модель живёт внутри `index.html` между метками `// ---- MODEL START` и
`// ---- MODEL END`, чтобы инструмент оставался одним переносимым файлом.
Тесты извлекают этот блок в модуль и гоняют его в Node.

## Родственный проект

[**steppe-fire-era5**](https://github.com/USERNAME/steppe-fire-era5) —
ретроспективная версия. Вместо прогноза из выбранной точки он берёт реальные
термоточки NASA FIRMS за прошедшую дату, собирает их в очаги, ведёт ту же
модель по ветру из реанализа ERA5 и сверяет расчётное направление с тем,
как пожары двигались на самом деле между пролётами спутника.

Та же физика, обратное направление во времени: здесь вопрос «что будет,
если», там — «что произошло».
